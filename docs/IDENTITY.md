# Project Identity

Decision date: 2026-07-25

## Selected identity

**OpenGlass UI** is the owner-approved public brand for this project.

Use the identity consistently:

| Surface | Identity |
| --- | --- |
| Display name | `OpenGlass UI` |
| Public npm facade | `open-glass-ui` |
| Repository slug | `open-glass-ui` |
| Workspace packages | `@open-glass-ui/*` |
| Runtime namespace | `ogui` |
| Tagline | `The open-source Liquid Glass UI system for React and the web.` |

The local working directory may continue to use its historical folder name.
Local folder names do not determine the eventual GitHub repository or npm
package names.

## Naming rationale

OpenGlass UI won the final search-led naming sprint because it combines:

- Immediate relevance to glass interface components.
- An explicit open-source signal.
- Clear pronunciation and predictable spelling.
- A package-friendly form for npm, GitHub, search engines, and AI coding agents.
- Enough room to contain React components, CSS materials, SVG refraction,
  optional WebGL rendering, recipes, tokens, and future framework adapters.

The official descriptor should carry the more saturated search phrase:

> OpenGlass UI is an open-source Liquid Glass UI system for React and the web.

This two-layer identity preserves search relevance without using “Liquid Glass”
as the project’s primary brand.

## Preliminary availability evidence

On 2026-07-25, exact automated checks did not find published npm packages for
either `open-glass-ui` or `openglassui`. NamingSignal also reported the exact
`openglassui` npm and GitHub account forms as likely unused and
`openglassui.dev` as likely unregistered.

These are time-bound availability signals, not reservations, guarantees, or
legal clearance. Repository slugs are owner-specific, npm names can be reserved
or claimed later, and automated checks do not establish trademark rights.

## Publication gate

The identity decision authorizes local architecture, copy, and package metadata
work. It does **not** authorize:

- Creating a GitHub remote or organization.
- Purchasing or configuring a domain.
- Publishing an npm package.
- Deploying the documentation site.
- Claiming registration or trademark clearance.

Recheck exact namespaces immediately before reservation or publication. A
qualified trademark review should assess confusing similarity, related
goods/services, and common-law use rather than exact text alone.
