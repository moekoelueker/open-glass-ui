# Naming Research

Decision date: 2026-07-25 (America/Los_Angeles)

## Selected identity

The owner selected **OpenGlass UI** as the public display name.

| Surface                     | Selected form                                                   |
| --------------------------- | --------------------------------------------------------------- |
| Display name                | `OpenGlass UI`                                                  |
| Public npm facade           | `open-glass-ui`                                                 |
| Repository slug             | `open-glass-ui`                                                 |
| Internal workspace packages | `@open-glass-ui/*`                                              |
| Runtime prefix              | `ogui`                                                          |
| Descriptor                  | `The open-source Liquid Glass UI system for React and the web.` |

The brand is broad enough to cover neutral themes, forty React recipes,
CSS-first materials, SVG/SDF refraction, optional WebGL, and future adapters.
The descriptor carries the category phrase; the primary brand avoids presenting
the project as an Apple implementation.

## Evidence reviewed

The local NamingSignal sprint generated, checked, ranked, and researched
hundreds of candidates before the owner made the final judgment. Its final
record scored **Open Glass UI** 80/100 (“Worth investigating”), including:

| Dimension         | Signal |
| ----------------- | -----: |
| Strategic fit     |     91 |
| Domain posture    |     93 |
| Namespace posture |     91 |
| Pronunciation     |     92 |
| Distinctiveness   |     46 |

The low distinctiveness score is important: “open” and “glass” are descriptive
category roots. The name is clear and discoverable, but clarity does not make it
legally exclusive.

Time-bound exact checks reported:

- no published npm package at the checked `open-glass-ui` or `openglassui`
  forms;
- a 404 for the exact `openglassui` GitHub account check;
- registry-absence signals for `openglassui.dev` and `openglassui.com`; and
- no exact normalized title in the first fifty checked US App Store results.

The automated sprint also recorded unresolved broader namesake and trademark
similarity work. Its raw evidence and timestamps remain in the developer's
local `docs/naming/naming-signal-ledger.json`. That large ledger is deliberately
git-ignored, private/local research evidence: it is not part of the public
repository, package, or marketing copy, and it may contain third-party search
responses that should not be republished wholesale.

For an authorized local rerun, copy `.env.example` to `.env.local` and set
`NAMING_SIGNAL_API_KEY` there. Both `.env.local` and the raw ledger stay
git-ignored; never commit, print, or paste the credential into documentation,
logs, or chat.

## Caveat

These checks are preliminary research, not reservations, guarantees, trademark
clearance, or legal advice. A 404 can mean only that an exact API or registry
record was absent at that moment. It does not establish:

- that a package, account, or domain can still be registered;
- that an owner has superior rights;
- that a similar mark is safe for related goods/services;
- that no common-law or jurisdiction-specific use exists; or
- that a descriptive name is protectable.

Immediately before any public reservation or release, repeat exact namespace
and domain checks and perform a human confusing-similarity search covering
related software, component libraries, design systems, and common-law use.
Professional trademark review is appropriate before material launch investment.
